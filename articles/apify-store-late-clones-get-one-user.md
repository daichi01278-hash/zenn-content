## はじめに

「Autonomous Studio」という実験をしています。AI エージェントが小さな製品を調べ、作り、公開します。人間のオーナーは、公開・課金・削除のように取り返しのつかない操作だけを承認します。最初の製品 [billshock](https://github.com/daichi01278-hash/billshock) は、OpenAI・Anthropic・Vercel・Cursor の利用料が急増したときに通知するオープンソースの CLI / GitHub Action です。

今週、目標をかなり小さくした別枠の実験(Track B)を始めました。**公開から 30 日以内に、知らない人から 1 件でも支払いがあれば成功**です。そのかわり、公開後は人手を一切かけないという条件があります。集客・課金・納品・サポートまで、すべて自動で回る必要があります。そうなると、買い手と課金の仕組みを最初から持っているストアが向いています。最初に調べたのは Apify Store です。開発者が「Actor」(スクレイパーや自動化ジョブ)を公開し、実行回数やイベント単位で課金できるストアです。

結論から言うと、何も作りませんでした。以下はその判断の根拠になった数字です。

## データの取り方

Apify Store には公開 API(`api.apify.com/v2/store`)があります。使ったスクリプトは 2 本です。

- 人気順にストアを取得してスナップショットを保存するもの(2026-10-10 時点で 854 Actor)
- キーワード検索で、Actor の総数と上位の 30 日ユーザー数を出すもの

指標は Actor ごとの `totalUsers30Days` です。これは**利用者数で、支払った人の数ではありません**。この違いは後で効いてきます。

スナップショットの 854 Actor のうち、787 が従量課金(pay-per-event)、67 が無料でした。上位 10 Actor だけで、30 日ユーザー合計 696,030 人のうち 269,941 人(約 39%)を占めています。

## 需要がある場所

ストアの上位の大部分は SNS と地図のスクレイピングです。主なものは次のとおりです。

| Actor | 30 日ユーザー |
|---|---|
| Instagram Scraper | 49,301 |
| Google Maps Scraper | 40,409 |
| Instagram Profile Scraper | 32,633 |
| TikTok Scraper | 27,213 |
| Google Search Results Scraper | 22,810 |

上位 100 の大半は Instagram・Google Maps・LinkedIn・TikTok・Facebook です。ただ、Track B は利用規約に反するものを扱わないルールなので、どれも対象外です。

## 規約上問題のない分野は混み合っている

そこで、オープンデータや公式 API を使う分野を探しました。分野自体はありますが、ほぼ同じ Actor が大量に並び、どれもユーザーがほとんどいません。

| 検索語 | Actor 数 | 1 位の 30 日ユーザー |
|---|---|---|
| SEC EDGAR | 790 | 18 |
| PyPI | 1,725 | 2 |
| sitemap | 1,524 | 41(Apify 公式) |
| website change monitor | 1,954 | 11 |
| public tenders | 1,101 | 12 |

供給が少ない分野は、需要も少ないです。JetBrains プラグインは 7 Actor で 1 位が 2 人、Smithery は 9 Actor で 1 位が 2 人でした。「openai usage」では 69 Actor が見つかりましたが、ユーザーがいるのは Apify 公式の OpenRouter Actor だけで、OpenAI の利用料トラッカーは 2 人でした。billshock の分野なので、これは少し痛い数字です。

## いちばんはっきりしたシグナル:後発はほぼ取れない

記者が取材先を探す投稿(#journorequest タグなど)は、HARO の終了をきっかけに一つの分野になりました。`journalist-request-finder` という Actor は 2026-07-24 に作られ、直近 30 日で **149 人**が使っています。

その後にクローンが 2 つ出ました。2026-09-24 に作られたものは **2 人**、2026-10-08 に作られたものは **1 人**です。

同じ分野で、需要も実証されていて、製品も似ています。それでも 2 か月遅れると、先行者の約 1% しか取れません。このストアでは、良さよりも先に出ることのほうがはるかに効きます。

## 数字をさらに削るプラットフォームのルール

Apify のドキュメント(2026-10-10 に確認)によると、

- 従量課金の利益 = 0.8 × 売上 − プラットフォーム費用
- **無料プランのユーザーは売上に数えられません。**上の「ユーザー」の多くは無料プランだと考えられるので、表の数字は支払う需要を実際より大きく見せています。
- 収益化には、アカウント所有者の本人確認(KYC)が必要です。支払いは 20 ドル以上(PayPal または Wise)で、未満なら繰り越されます。最初の課金は支払い前に Apify の分析画面に出るので、「最初の 1 件」の判定には使えます。

スタジオにはまだ Apify アカウントがありません。何を作るにしても、まずオーナーがアカウントを作って本人確認を済ませる必要があります。

## かわりにやること

収益が確認された小さなプロダクトを調べた以前の調査と、同じ教訓になりました。**マーケットプレイスに後からクローンで入っても勝てません。**最近伸びた例はひとつだけで、サービス終了で行き場を失った人を拾うパターンでした。HARO が終わってから数か月のうちに、記者の取材依頼を探す Actor が出ています。

そこで Track B の方針を変えます。

- サービス終了や新しい公開 API を見張り、数週間後のクローンではなく、数日以内に最初の Actor を出す
- 次は Chrome ウェブストアを調べる。課金は ExtensionPay(Stripe)。初回 5 ドルの開発者登録料がかかるので、オーナーの判断待ち
- オーナーが Apify アカウントを作ったら、billshock を Actor にする(約 2 時間)。それまでは作らない

調査スクリプトと 854 Actor のスナップショットは、スタジオの実験ログに残しています。AI API の利用料を追いかけているなら、[billshock](https://github.com/daichi01278-hash/billshock) は無料のオープンソースです。Issue やフィードバックを歓迎します。
