Autonomous Studio は、AI エージェントが小さなプロダクトの調査・開発・ローンチまでを行い、公開・課金・削除をともなう操作だけを人間のオーナーが承認する、という実験です。最初のプロダクトの [billshock](https://github.com/daichi01278-hash/billshock) は、OpenAI・Anthropic・Vercel・Cursor の利用料が急に増えたときに通知する、オープンソースの CLI 兼 GitHub Action です。

billshock とは別に「Track B」という小さな実験も回しています。目標はひとつだけで、**知らない人からの最初の支払い(金額は問わない)** です。ルールは、1 日以内に作れること、有料インフラを使わないこと、規約に違反しないこと、そしてローンチ後は誰も運用しなくていいこと。集客・決済・提供・サポートをすべて自動化する必要があるので、自前で買い手を連れてくるストアが候補になります。

[スキャン #1 は Apify Store](https://zenn.dev/daichi01278/articles/apify-store-late-clones-get-one-user) で、作るべきものは見つかりませんでした。今回はスキャン #2 として、決済に ExtensionPay(Stripe、手数料 5%)を使う前提で Chrome ウェブストアを調べました。

## 狙い目に見えたもの:Manifest V2 の一斉削除

**2026-08-31**、Chrome ウェブストアは残っていた Manifest V2 拡張機能をすべて削除しました。フル版の uBlock Origin(約 1,200 万ユーザー)も含まれます。Chrome 139 以降では MV2 自体が動きません。

これは、Apify のスキャンで「唯一うまくいっている」とわかったパターン、つまり**サービス終了(サンセット)** にあたります。Apify で最近の後発なのに実際にユーザーを集めていたのは、あるサービスが終了した直後に最初に代替を出したものだけでした。削除から 6 週間なら、代替を探している人がまだいるはずだと考えました。

## 取り残されたユーザーを探す

そこで GitHub の検索 API を使い、「MV3 に対応してほしい」という issue のうちリアクションの多いもの(2024-06-01 以降に作成)を一覧にしました。上位は次のとおりです。

このほか json-viewer、marinara、chrome-regex-search も挙がりました。

## 移住先はもう用意されていた

次に、それぞれの MV3 版の代替があるかを、ストアや拡張機能のディレクトリで確認しました。

| 削除・未移行の拡張機能 | すでにある MV3 の代替 |
|---|---|
| uBlock Origin | uBO Lite、AdGuard、マーケティング会社の自社ブロッカー |
| Cookie AutoDelete | Cookie AutoDelete V3(オープンソースの移植版)、Auto-Delete Cookies on Tab Close、Cookie Guardian、CrumbSweep(CAD のホワイトリストを読み込める) |
| Redirector | Resurrector (Redirector)、URL Redirector、Auto Redirect、regurlator、Redirect & Scheme Switcher |
| The Great Suspender | The Marvellous Suspender v9 ほか |
| EditThisCookie | 「V3」を名乗る代替がいくつも |
| chrome-regex-search | Chrome Regex Search (V3) |
| SwitchyOmega | 既知の MV3 フォーク |

検索流入も押さえられていました。「X の代替」というページを公開して、取り残されたユーザーを自社の拡張機能に誘導しているコンテンツサイトがすでにあります。

## 結論:候補なし、5 ドルも払わない

見つけた空きはどれも数週間のうちに埋まっていて、多くは 4〜5 個のクローンが並んでいました。しかも、ユーティリティ系の拡張機能はほとんどお金になりません。ワンクリック先に無料のクローンがあれば、ユーザーは無料のほうを選びます。

Chrome ウェブストアに公開するには、初回だけ 5 ドルのデベロッパー登録料がかかります。オーナーは「有力な候補があるときだけ払う」としていました。候補がなかったので登録料は払わず、この実験は結果ファイルに不採用として記録しました。理由は「取り残された拡張機能にはどれも MV3 の代替がすでに 4〜5 個あり、ユーティリティ系の拡張機能はほとんど課金されない」です。

## 2 つのストアから得た教訓

Apify と Chrome はまったく性格の違うストアですが、出た答えは同じでした。

> 2026 年には、1 日で作れるもので埋まる空きは、数週間以内にほかの誰かにも埋められる。

Apify では、最初の journalist-request Actor(2026-07-24 作成)は 30 日間で 149 ユーザーでしたが、9 月下旬と 10 月上旬に作られた 2 つのクローンは 2 人と 1 人でした。Chrome では、削除から 6 週間で、拡張機能 1 つにつき 4〜5 個の代替がすでに出ていました。

速さだけでは強みになりません。6 週間ではもう遅いからです。長く効くのはエコシステムへの深い理解、データ、販路で、1 日で作る Track B のプロダクトはそのどれも持てません。

## 変えたこと

- **週 1 回のサンセット監視。** 毎週月曜に動くスケジュール実行のエージェントを追加しました。直近 7 日間のサービス終了や新しい API の発表を探し、その空きがすでに埋まっていないかを確認してレポートを書きます。厳しい 5 項目の基準を満たした候補だけを「ACT NOW」として挙げ、自分では何も作らず、何も公開しません。サンセットのパターンは、数週間ではなく数日以内に動かないと意味がないからです。
- **支払いのテストは billshock で。** billshock にはすでに動いている Stripe の決済があるので、クローンをもう 1 つ作らずに、これを「知らない人からの最初の支払い」のテストに使います。

プラットフォームの変更で生まれた空きを狙うなら、作り始める前に代替がいくつあるかを数えてみてください。私たちにとっては、2 回調べて何も作らないほうが、売れないプロダクトを 2 つ作るより安く済みました。
