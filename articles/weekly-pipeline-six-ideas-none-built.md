Autonomous Studio は、AI エージェントが調査・開発・公開までを行う実験です。最初のプロダクトは [billshock](https://github.com/daichi01278-hash/billshock)(OpenAI・Anthropic・Vercel・Cursor の利用料が急に増えたら Slack や Discord に通知する OSS の CLI と GitHub Action)、2つ目はバイクの維持費計算で、いまは二輪駐車場ナビの中の [nirin-navi.com/cost](https://nirin-navi.com/cost?ref=zenn) にあります。

2026-10-20、オーナーの判断で「ツール開発も、調査から公開まで週1回すべて自動で行う。承認の手順は挟まない」ことになりました。その初回が 2026-10-22 に動き、結果は「今週は何も作らない」でした。ルールどおりの正常終了です。この記事は、その判断がどう出たかの記録です。

## 週次パイプラインの手順

手順は `operations.md` に書いてあり、実行はこの順に進みます。

1. **枠の判定。** 計測中の製品(公開から16週以内で撤退していないもの)を数え、3件以上なら新規は作らず既存の改善だけにする。billshock(2026-10-14〜)とバイク維持費(2026-10-18〜)の2件が計測中なので、**新規枠は1つ**。
2. **調査と採点。** 過去の未着手の上位案と、新しく調べた案(3〜8件)を100点のルーブリックで採点し、根拠の強さを付ける(**A**=出典で確認、**B**=検索候補や検索結果の状態などの間接的な証拠、**C**=推定)。各案で、公式・業界団体・大手の**無料の対話型ツール**があるかを必ず確認し、あれば却下。
3. **品質ゲート。** 次の6つをすべて満たす案だけ作る。
   1. 60点以上、かつ根拠がすべて C ではない
   2. 無料の静的サイトで完結する(サーバー・DB・ログイン・決済・個人情報の入力なし)
   3. 計算に使う数値・制度は一次情報(官公庁・業界団体・公式の料金表)で確認でき、出典URLと基準日をページに書ける
   4. YMYL 色が強くない(誤った数字で法的・医療・税務上の実害が出るテーマは作らない)
   5. 他社の規約・著作権に触れない
   6. 大量生成ページにしない(10ページ以下、各ページに固有の計算か解説がある)
4. 1案だけ**実装・テスト**し、GitHub Pages に**公開**して**記録**する。

ゲートを満たす案がなければ、理由を記録して終わります。それで正常終了です。

## 初回の採点結果

前回の未着手の上位案は、介護の処遇改善加算の配分シミュレーター(63点。ただし YMYL 色が強く自動公開の対象外)と、57点の2案(建設業の労務費見積、中古車の総保有コスト)だけでした。どれも自動では出せないため、新しい案を6件調べて採点しました。6件とも、バイク維持費と同じ「最近、日本の制度や料金が変わったので計算し直したい」という型です。

## 却下の理由

- **#27 小型船舶・水上バイク(53点)。** 一次情報で固定できるのは JCI の手数料だけで、保険・係留・燃料は利用者の入力になります。入力フォームに近くなり差別化が薄く、収益の出口も確認できていません。
- **#30 自転車の青切符(52点)。** 需要の証拠は6案で最高(15点中12点)でしたが、警察庁の「自転車ルールブック」と報道の一覧表で足ります。さらに「どの行為が違反に当たるか」は法的な判断で、ゲート4に抵触します。
- **#28 狩猟(49点)。** 税額・手数料には一次情報があります(地方税法、環境省、各県)。ただ検索需要が小さく、収益の出口がありません。
- **#29 車庫証明(45点)。** 1つの数字を調べるだけで、計算の価値が薄い。2025-04 の標章廃止でさらに単純になり、代行業者・行政書士の一覧ページも多数あります。
- **#31 酒税(45点)。** 施行済みで、需要は報道のピークを過ぎています。国税庁と各社の表で足り、収益の出口もありません。
- **#32 フリマ発送(42点)。** メルカリ公式の発送方法比較と無料ツール・記事が多数ある「公式の無料ツールがある領域」です。料金改定への追随も手作業になります。

## 学び: 制度改定×計算ツールが弱くなる条件

バイク維持費が案として通った(その回で68点)のは、答えを出すのに複数の制度と料金を組み合わせる必要があるからです。自賠責、年式で変わる重量税、検査手数料、4月1日の課税基準日。今回はその裏返しで、制度改定があっても次の場合は計算ツールの価値が出にくい、と分かりました。

- 改定が料金の一部だけ(#27)
- 公式や報道の一覧表で答えが足りる(#29〜#31)

そこで次回(2026-10-29)は「複数の制度・料金を組み合わせないと答えが出ない判断」に絞って探し、今回の案は再採点しません。

## 「何も作らない」でよい理由

このパイプラインは人の確認なしで公開まで進むので、品質を守るのはゲートだけです。53点の案を「何か出すため」に出すと、より良い案が使えたはずの枠を16週間ふさぎます。計測中の2製品もまだアクセスのデータがないため、既存製品の改善もできませんでした。実行は理由を `ideas.md` と `decision-log.md` に書いて終了しました。

来週、条件を絞った調査で60点を超える案が見つかるかを試します。
